# VeriSafe - API Specification

**Version:** 1.0.0-draft  
**Base URL:** `/api`  
**Team:** Team Shadow Paradox  
**Tagline:** Detect. Understand. Verify.  

---

## 1. Important Notice: Nature of Assessments

> ⚠️ **DISCLAIMER:**  
> All risk ratings (`Low`, `Medium`, `High`, `Needs Review`) generated by the VeriSafe API are **preliminary risk assessments based on heuristic signals, structural attributes, and pattern matching**. They are **NOT guarantees** that an entity is entirely safe or definitively malicious.  
> 
> Security decisions involving sensitive transactions, credential inputs, or critical data should never rely solely on an automated score; users must perform independent out-of-band verification.

---

## 2. Risk Classification System

Every analysis response includes a `risk_level` field assigned to one of four standardized classifications:

| Risk Level | Classification | Meaning & Operational Guidance | Typical Indicators |
| :--- | :--- | :--- | :--- |
| **`Low`** | Minimal Risk Detected | No strong indicators of fraud, coercion, or deception were detected. Normal digital vigilance is still advised. | Standard communication syntax, well-established legitimate domains, absence of urgent financial or credential requests. |
| **`Medium`** | Suspicious / Elevated Risk | One or more anomalous indicators found. The content or link presents non-trivial risk; caution is strongly recommended. | Mild urgency phrasing, suspicious URL parameters, unfamiliar or newly registered top-level domains, mismatched display names. |
| **`High`** | High Likelihood of Malice | Strong evidence of fraudulent or phishing intent detected. Direct interaction is dangerous. | Credential harvesting requests (passwords, OTPs), homoglyph/typosquatted domains, IP-address-based URLs, impersonation of financial institutions. |
| **`Needs Review`** | Inconclusive / Ambiguous | The input cannot be classified with high confidence due to conflicting signals, insufficient context, or obfuscation. | Obfuscated text, truncated URLs, non-standard encoding, or signals that equally match legitimate business patterns and phishing lures. |

---

## 3. Global Conventions & Standards

- **Protocols:** HTTPS is required for all external interactions.
- **Content Type:** `application/json` for both request payloads and response bodies.
- **Timestamps:** ISO 8601 UTC format (e.g., `2026-10-29T01:30:00Z`).
- **Identifier Format:** Unique analysis identifiers prefixed with an identifier tag (e.g., `msg_anlz_...`, `url_anlz_...`).

## 4. Endpoints

### 4.1. Health Check

Checks service availability, operational readiness, and API version.

- **Authentication:** None
- **Request Headers:** None required

### 4.2. Message Analysis

Analyzes suspicious message content (emails, SMS text, direct messages) for phishing cues, urgency, coercion, and credential harvesting patterns.

- **Endpoint:** `POST /api/messages/analyze`
- **Authentication:** Optional / Hackathon Open
- **Request Headers:**
  - `Content-Type: application/json`

#### Request Payload Schema

| Field | Type | Required | Constraints | Description |
| :--- | :--- | :--- | :--- | :--- |
| `message_text` | `string` | **Yes** | 1 to 50,000 characters | The raw text of the message to inspect. |
| `sender` | `string` | No | Max 255 characters | Sender display name, phone number, or email address. |
| `channel` | `string` | No | Enum: `email`, `sms`, `chat`, `social`, `other` | The communication channel where the message appeared. Default: `other`. |

#### Example Request

```json
{
  "message_text": "URGENT: Your bank account has been locked due to suspicious activity. Click here immediately to verify your identity and enter your OTP: http://192.168.1.1/verify-bank",
  "sender": "security-alert@verify-online-bank.cc",
  "channel": "sms"
}
```

#### Success Response Schema (`200 OK`)

| Field | Type | Description |
| :--- | :--- | :--- |
| `analysis_id` | `string` | Unique tracking identifier for this analysis. |
| `timestamp` | `string` | ISO 8601 timestamp of analysis completion. |
| `input_summary` | `object` | Summary of evaluated message metadata (length, extracted links, etc.). |
| `risk_level` | `string` | Classification: `Low`, `Medium`, `High`, or `Needs Review`. |
| `confidence_score` | `number` | Float between `0.00` and `1.00` reflecting detector confidence. |
| `assessment_disclaimer` | `string` | Formal notice that this is an advisory assessment, not a guarantee. |
| `summary` | `string` | Human-readable explanation summarizing the core findings. |
| `indicators` | `array` | List of granular indicator objects detailing flagged risks. |
| `indicators[].category` | `string` | E.g., `urgency`, `credential_solicitation`, `sender_impersonation`, `embedded_url`. |
| `indicators[].signal` | `string` | Concise title of the observed signal. |
| `indicators[].severity` | `string` | Severity of this individual signal: `low`, `medium`, `high`, `critical`. |
| `indicators[].explanation` | `string` | Clear description explaining why this pattern represents a threat. |
| `indicators[].matched_text` | `string` (optional) | The specific substring or snippet triggering the indicator. |
| `recommendations` | `array of strings` | Concrete steps the user should follow to verify safely. |

#### Example Success Response (`200 OK`)

```json
{
  "analysis_id": "msg_anlz_9b1e2c84a0d2",
  "timestamp": "2026-10-29T01:30:15Z",
  "input_summary": {
    "channel": "sms",
    "char_count": 142,
    "detected_urls": [
      "http://192.168.1.1/verify-bank"
    ]
  },
  "risk_level": "High",
  "confidence_score": 0.94,
  "assessment_disclaimer": "This is a preliminary risk assessment based on automated pattern detection, not a security guarantee. Always verify through official channels.",
  "summary": "This message exhibits strong phishing indicators including high artificial urgency, sensitive OTP credential solicitation, and an unencrypted IP-based link.",
  "indicators": [
    {
      "category": "urgency",
      "signal": "Artificial Time Pressure",
      "severity": "high",
      "explanation": "Phrases like 'URGENT' and 'immediately' are routinely used by attackers to induce panic and prompt impulsive actions before verification.",
      "matched_text": "URGENT: Your bank account has been locked"
    },
    {
      "category": "credential_solicitation",
      "signal": "Sensitive OTP / Credential Request",
      "severity": "critical",
      "explanation": "Legitimate banking institutions do not request one-time passwords (OTPs) or security credentials via incoming SMS links.",
      "matched_text": "enter your OTP"
    },
    {
      "category": "embedded_url",
      "signal": "Direct IP-Based Unencrypted URL",
      "severity": "critical",
      "explanation": "The link uses a bare IP address and unencrypted HTTP, which is common in phishing attacks attempting to evade domain reputation filters.",
      "matched_text": "http://192.168.1.1/verify-bank"
    }
  ],
  "recommendations": [
    "Do not click the link or supply your one-time password (OTP).",
    "Contact your bank directly by typing their official website into your browser or calling the number on the back of your card.",
    "Report the message as spam or phishing to your cellular carrier."
  ]
}
```

### 4.3. URL Analysis

Evaluates a target URL and its domain infrastructure for structural phishing indicators, impersonation, typosquatting, and risky hosting anomalies.

- **Endpoint:** `POST /api/urls/analyze`
- **Authentication:** Optional / Hackathon Open
- **Request Headers:**
  - `Content-Type: application/json`

#### Request Payload Schema

| Field | Type | Required | Constraints | Description |
| :--- | :--- | :--- | :--- | :--- |
| `url` | `string` | **Yes** | Valid URI format, max 2048 characters | The target web link to evaluate. |
| `context` | `string` | No | Max 500 characters | Optional context where the URL was found (e.g., "SMS from PayPal"). |

#### Example Request

```json
{
  "url": "https://secure-login.paypa1-update.com/account/login",
  "context": "Received in an email claiming my account was suspended"
}
```

#### Success Response Schema (`200 OK`)

| Field | Type | Description |
| :--- | :--- | :--- |
| `analysis_id` | `string` | Unique tracking identifier for this URL analysis. |
| `timestamp` | `string` | ISO 8601 timestamp of analysis completion. |
| `target_url` | `string` | Original input URL. |
| `normalized_url` | `string` | Canonicalized URL examined by the engine. |
| `risk_level` | `string` | Classification: `Low`, `Medium`, `High`, or `Needs Review`. |
| `confidence_score` | `number` | Float between `0.00` and `1.00`. |
| `assessment_disclaimer` | `string` | Formal notice that this is an advisory assessment, not a guarantee. |
| `domain_details` | `object` | Parsed breakdown of the URL and domain anatomy. |
| `domain_details.domain` | `string` | Hostname (e.g., `paypa1-update.com`). |
| `domain_details.tld` | `string` | Top-level domain (e.g., `com`). |
| `domain_details.subdomains` | `array of strings` | List of subdomains (e.g., `["secure-login"]`). |
| `domain_details.is_ip_address` | `boolean` | Indicates if host is an IPv4/IPv6 address. |
| `domain_details.has_homoglyphs` | `boolean` | Indicates if punycode or lookalike characters are present. |
| `summary` | `string` | Human-readable explanation of domain evaluation. |
| `indicators` | `array` | List of flagged structural indicators. |
| `recommendations` | `array of strings` | Actionable safety advice for navigating the site. |

#### Example Success Response (`200 OK`)

```json
{
  "analysis_id": "url_anlz_4f7a1e5d83c9",
  "timestamp": "2026-10-29T01:31:00Z",
  "target_url": "https://secure-login.paypa1-update.com/account/login",
  "normalized_url": "https://secure-login.paypa1-update.com/account/login",
  "risk_level": "High",
  "confidence_score": 0.96,
  "assessment_disclaimer": "This is a preliminary risk assessment based on automated pattern detection, not a security guarantee. Always verify through official channels.",
  "domain_details": {
    "domain": "paypa1-update.com",
    "tld": "com",
    "subdomains": [
      "secure-login"
    ],
    "is_ip_address": false,
    "has_homoglyphs": true
  },
  "summary": "This URL uses typosquatting to impersonate PayPal (substituting the letter 'l' with the digit '1') paired with deceptive login subdomains.",
  "indicators": [
    {
      "category": "typosquatting",
      "signal": "Character Substitution (Homoglyph/Look-alike)",
      "severity": "critical",
      "explanation": "The domain 'paypa1-update.com' replaces the letter 'l' with the number '1' to mimic PayPal.",
      "matched_text": "paypa1"
    },
    {
      "category": "subdomain_deception",
      "signal": "Misleading Security Subdomain",
      "severity": "high",
      "explanation": "Subdomains like 'secure-login' are frequently prepended to deceive users into assuming the site is an authentic authentication portal.",
      "matched_text": "secure-login"
    }
  ],
  "recommendations": [
    "Do not visit this URL or enter credentials.",
    "Navigate to the official provider by manually navigating to paypal.com in a new browser tab.",
    "Report this domain to anti-phishing authorities."
  ]
}
```

## 5. Validation Errors & Error Handling

When a request cannot be fulfilled, the API returns a structured error object with an appropriate HTTP status code.

### Error Response Schema

| Field | Type | Description |
| :--- | :--- | :--- |
| `error.code` | `string` | Machine-readable error code (e.g., `VALIDATION_ERROR`, `BAD_REQUEST`). |
| `error.message` | `string` | Human-readable explanation of the failure. |
| `error.details` | `array` | Granular list of field-level validation errors. |
| `error.timestamp` | `string` | ISO 8601 timestamp of the error occurrence. |

### Common Status Codes

| Status Code | Code String | Description |
| :--- | :--- | :--- |
| **`400 Bad Request`** | `MALFORMED_JSON` / `INVALID_SYNTAX` | Request body is not valid JSON or syntax is malformed. |
| **`422 Unprocessable Entity`** | `VALIDATION_ERROR` | Payload failed schema validation (missing required fields, out-of-range length, invalid URL format). |
| **`429 Too Many Requests`** | `RATE_LIMIT_EXCEEDED` | Request rate exceeded allowable threshold. |
| **`500 Internal Server Error`** | `INTERNAL_ERROR` | An unexpected server error occurred during analysis. |

#### Example: 422 Unprocessable Entity (Empty message)

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The submitted payload failed validation constraints.",
    "timestamp": "2026-10-29T01:31:20Z",
    "details": [
      {
        "field": "message_text",
        "issue": "Field is required and must contain at least 1 character.",
        "received": ""
      }
    ]
  }
}
```

#### Example: 422 Unprocessable Entity (Invalid URL)

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The submitted URL could not be parsed as a valid URI.",
    "timestamp": "2026-10-29T01:31:30Z",
    "details": [
      {
        "field": "url",
        "issue": "Invalid URL scheme or format. Must be an HTTP or HTTPS URL.",
        "received": "not-a-valid-url"
      }
    ]
  }
}
```

#### Example: 400 Bad Request (Malformed JSON)

```json
{
  "error": {
    "code": "MALFORMED_JSON",
    "message": "Request body could not be parsed as valid JSON.",
    "timestamp": "2026-10-29T01:31:40Z",
    "details": []
  }
}
```
